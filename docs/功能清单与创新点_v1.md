## 二、项目创新点

### 1. 证据闸门（Evidence Gate）——反幻觉/反误报的漏洞治理
借鉴 muteki 的 gate 理念：**任何漏洞发现必须携带原始工具输出证据才能进入 confirmed 状态**。nuclei 的完整 JSON（HTTP 请求报文、CWE/CVSS 分类、模板来源、matcher 结果）原样存入 `Vulnerability.evidence`，LLM 分诊与人工确认都基于原始证据，杜绝"幻觉漏洞"。误报确认后可进 Dead-end 跳过清单（规划中）。

### 2. 授权边界即代码（Authorized-Scope-as-Code）
nuclei/naabu 等主动扫描工具的**每次调用都经过 `in_scope()` 前置校验**（域名后缀/IP/CIDR 白名单），空授权一律拒绝。端到端验证中该机制正确阻止了对第三方资产的扫描——合规性与扫描能力在同一抽象层强制执行，而非依赖流程约定。

### 3. 分级降级策略——"不产假数据"原则
全链路每个外部依赖（CLI 工具、第三方 API、搜索引擎）都有明确的降级路径：真实源 → 备用源 → 显式记录能力缺口返回空。**stub 数据仅在开发模式（`*_use_stubs=True`）下存在**，线上失败宁可空结果+日志，绝不虚构数据污染下游情报/资产/漏洞。

### 4. 持久化 Checkpoint 的可恢复攻击面管线
LangGraph + AsyncSqliteSaver（thread_id=task.id）实现**企业级攻击面评估的断点续跑**：M0-M6 长流程（云图采集、子域枚举、DNS、端口扫描、漏扫可能耗时数小时）中进程崩溃后从最后完成的节点恢复，已产出数据不重复执行。节点重放幂等性（completed 去重、进度钳制、资产 upsert、漏洞去重）保证多次恢复结果一致。

### 5. 声明式工具治理
外部安全工具（subfinder/dnsx/httpx/naabu/nuclei/nmap）以 **YAML/代码声明的 ToolDefinition 注册**：参数 schema + 输入类型校验（防注入）+ 白名单 flags + 固定 JSON 输出 + 解析器 + 探活安装脚本。借鉴 CyberStrikeAI 的 100+ 工具配方理念，新增工具只需注册定义，不改管线代码。

### 6. 多来源证据融合的资产置信度
同一资产被多个独立来源（subfinder/dnsx/httpx/naabu/证书）命中时，置信度按来源数加权提升（封顶 1.0），端口/技术栈取并集——单点误报被多来源交叉验证稀释，输出的是"证据加权"的资产视图。

### 7. 端到端可追溯闭环
企业名输入 → 云图主体 → 情报（真实 URL 可溯源）→ 关键词 → 资产（工具原始输出）→ 漏洞（evidence 闸门）→ 报告，**每层产物都带来源与证据元数据**，报告中的每个数字可回溯到原始采集记录。

## 三、下一步开发计划

### P0（本周可完成）

1. **报告内容增强**
   - 修 `reporting/aggregator.py` 字段填充：资产表补 IP/端口/技术栈/ICP 列（当前显示"—"）；
   - 报告模板增加「情报摘要」（M1 真实新闻/备案/招投标要点）与「关键词暴露面」章节，让 M1/M2 产出进入报告。
2. **vuln_judge LLM 分诊上线**：orchestrator vuln_judge 节点由 stub 改为真实 LLM 分诊——对 high/critical 发现评估 `false_positive_risk/reason`、`llm_confidence`，evidence 完整且高置信 → `confirmed`；人工标记误报写入 task 级跳过清单（Dead-end），后续扫描不再报。
3. **自定义 nuclei 模板支持**：支持按任务注入自定义模板（如针对 Yakit 靶场注入接口），验证注入类漏洞检出能力。

### P1（1-2 周）

4. **M4 接口爬取接入图**：将现有真实的 static_analyzer/classifier 接入企业管线（M4 目前预留），产出 ApiInterface 供 M5 接口级测试与报告引用。
5. **异步任务执行**：`POST /tasks/{id}/start` 改为后台 worker 执行（当前同步阻塞 9 分钟），配合 SSE/WebSocket 推送节点级进度事件（复用事件总线），前端实时展示 M0-M6 阶段进度。
